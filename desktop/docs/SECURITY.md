# NOCTRA STUDIO — Security Model

1. **Untrusted by Default**: External GitHub Skills, marketplace packages, and third-party MCP servers are flagged as `unverified` unless explicitly trusted by the user.
2. **No Automatic Script Execution**: Skill `scripts/` directories are scanned as metadata only and never executed automatically.
3. **Deterministic Tool Filtering**: An agent only receives tool definitions in its model request if the tool is globally enabled in MCP Hub, explicitly assigned to that agent, and (when in a project) permitted by the project scope.
4. **Path Containment**: Project file operations and agent file-scoped tool arguments are canonicalized and verified to stay within authorized root directories.
5. **Credential Isolation**: Secrets reside exclusively in OS Credential Storage (`noctra-studio` service) and are scrubbed from all logs and diagnostics.
6. **Internet Mode Guardrails**: Off by default per conversation. Built-in network security tools (`net_dns_lookup`, `net_port_scan`, `net_http_security_check`, `net_fetch_url`) block private/loopback/link-local/cloud-metadata IPs unless explicitly enabled, validate redirect hops against SSRF, enforce optional domain allowlists and bounded port/timeout/concurrency caps, require Review Mode approval before probing, and log all probes to the local audit log.
7. **SSH Server Automation Security**: Remote SSH credentials (passwords, inline PEM keys, and passphrases) are stored exclusively in OS Keychain (or kept in volatile RAM for session-only mode), registered with `SecretRedactor` so they never appear in logs or command outputs, and excluded from portable backups. Host keys are verified via Trust-On-First-Use (TOFU) SHA-256 fingerprints, Review Mode requires explicit user approval for command execution (`ssh_exec`) and file writes (`ssh_write_file`), and output streams are bounded and cancellable.
